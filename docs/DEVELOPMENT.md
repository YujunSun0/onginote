# 온기노트 개발 문서

기능 명세, 로컬 실행, 환경 변수, 구조, 결제, 배포를 정리한 문서입니다. 프로젝트 소개는 [README](../README.md)를 보세요.

말투와 성격이 다른 캐릭터 4명이 고민을 들어주고, 대화 흐름에 따라 들어주기 → 상황 해석 → 행동 플랜으로 넘어갑니다. 대화에서 알게 된 상대방 정보는 인물 프로필에 쌓입니다. 나중에 "걔 뭐 좋아했더라?" 싶을 때 찾아볼 수 있고, 다음 상담에서도 참고합니다.

> 전문 심리상담이나 의료 서비스를 대신하지 않습니다. 대화 중 위기 신호가 보이면 자살예방상담전화 109, 정신건강위기상담 1577-0199를 안내합니다.

## 주요 기능

### 상담

- 캐릭터는 4명입니다.
  - 몽글: 다정하고 느긋합니다.
  - 여울: 직설적이고 행동 위주입니다.
  - 올리: 차분하고 근거를 중시하며 존댓말을 씁니다.
  - 다온: 친구 같은 반말을 씁니다.
- 정해진 단계를 따라가지 않고, 메시지마다 지금 어떤 모드로 답할지 판단합니다.

  | 모드 | 언제 쓰는지 |
  |---|---|
  | 들어주기 | 하소연하는 중일 때. 조언 없이 공감만 합니다 |
  | 알아가기 | 해석할 정보가 거의 없을 때. 연속 2번까지만 묻습니다 |
  | 상황 해석 | "왜 이래?", "무슨 일이야?" 하고 물을 때. 가장 그럴듯한 이유를 골라서 말합니다. 두 번째부터는 달라진 점만 말합니다 |
  | 반응 | 사용자가 정정하거나 결정하거나 반박할 때. 그 말에 바로 답하고, 선택지를 다시 내밀지 않습니다 |
  | 플랜 제안 / 플랜 | 해결책이 필요할 때. 오늘 할 것, 하지 말 것, 보낼 말 초안을 줍니다 |

- 입력창 위 버튼("그냥 들어줘", "이제 해결책 볼래", "보낼 말 써줘")으로 모드를 직접 고를 수도 있습니다.
- 해석이나 플랜처럼 긴 답변은 카톡처럼 말풍선 2~3개로 나눠 보냅니다.
- 카톡 캡처는 한 번에 5장까지 보낼 수 있고, 캐릭터가 내용을 읽고 해석합니다.
- 해석과 플랜에서는 필요할 때만 "isfj 갑자기 잠수" 같은 일반적인 사례를 웹에서 찾아봅니다. 상대방 실명으로는 검색하지 않습니다.
- 말로 입력하고, 답변을 소리로 들을 수 있습니다. 지금은 브라우저 내장 기능을 씁니다.

### 정리와 기록

- 상담을 마치면 상황, 해석, 할 것, 하지 말 것을 정리 카드 한 장으로 만들어 줍니다.
- 대화에서 찾은 상대방 정보를 프로필에 저장할지 물어봅니다. 틀린 부분은 고쳐서 저장할 수 있고, 체크한 것만 저장됩니다.
- "우리 이야기" 타임라인에는 상담을 정리할 때마다 한 줄씩 쌓입니다. 프로필에서 직접 쓰거나 고칠 수도 있습니다.
- 선톡: 정리할 때 며칠 뒤 캐릭터가 먼저 보낼 안부 메시지를 만들어 둡니다. 홈 화면에 뜨고, 원하지 않으면 스위치로 끌 수 있습니다.
- 정리가 끝난 상담은 입력창이 잠깁니다. "이어서 얘기하기"로 다시 열면 나중에 다시 정리할 수 있습니다.

### 사람과 상담 목록

- 인물 프로필에는 MBTI, 나이, 생일(D-day), 좋아하는 것, 싫어하는 것, 연락 스타일, 메모, 우리 이야기를 기록합니다.
- 프로필의 "물어보기"에 "OO이 뭐 좋아했더라?"처럼 물으면 저장된 정보를 바탕으로 답합니다.
- 상담 탭에서 지금까지 나눈 상담을 모두 볼 수 있습니다. 정리 상태와 사람별로 걸러 볼 수 있습니다.
- 홈에는 정리 카드의 할 것을 모은 체크리스트와 다가오는 생일이 나옵니다.

### 약관과 AI 안내

- 이용약관(`/terms`), 개인정보 처리방침(`/privacy`), AI 답변 안내(`/ai-notice`)는 로그인 없이 열립니다. 로그인 화면과 마이페이지에서 링크합니다. 운영자 정보와 동의 버전은 `src/lib/legal.ts`에 있습니다.
- 처음 로그인하면 동의 화면(`/welcome`)에서 만 14세 이상, 이용약관, 개인정보 수집·이용, 민감정보 처리, 국외 이전(Anthropic, 미국)에 모두 동의해야 시작할 수 있습니다. 동의 전에는 모든 API가 403을 돌려줘서 대화가 국외로 전송되지 않습니다.
- 동의 여부는 로그인 토큰의 `app_metadata.consent_version`(서버만 바꿀 수 있음)으로 확인해서 요청마다 DB를 조회하지 않습니다. 약관을 바꿔 다시 동의를 받아야 하면 `CONSENT_VERSION`을 올립니다.
- AI 기본법의 투명성 의무에 맞춰 채팅 맨 위에 캐릭터가 AI라는 안내를 두고, 서비스 밖으로 가져갈 수 있는 정리 카드와 PDF에는 "AI가 정리한 내용"을 표시합니다.

### 마이페이지

- 닉네임(1~20자)을 바꿀 수 있습니다. 처음에는 카카오·구글 이름이 들어가고, 홈 인사("○○, 왔구나!")에 쓰입니다.
- 이메일, 로그인 방식, 가입일, 오늘 사용량, 사람·상담·정리 개수를 보여줍니다.
- 내 기록 전체를 PDF로 받을 수 있습니다. 인쇄용 화면(`/me/print`)이 열리면 인쇄 창에서 "PDF로 저장"을 고릅니다. 사람, 상담, 정리 카드, 사진이 모두 들어갑니다. 다른 서비스로 옮길 때 쓰는 JSON 파일도 받을 수 있습니다.
- 로그아웃과 회원 탈퇴가 있습니다. 탈퇴는 "탈퇴"를 직접 입력해야 진행됩니다.

### 화면 크기

- 모바일과 태블릿에서는 한 줄 화면에 하단 메뉴를 씁니다.
- PC(1024px 이상)에서는 왼쪽 세로 메뉴가 생기고, 상담과 사람들 화면은 왼쪽에 목록을 띄운 채 오른쪽에서 내용을 봅니다.
- 더 넓은 화면(1280px 이상)에서는 채팅 오른쪽에 상담 중인 사람의 프로필 패널이 붙습니다. 헤더 버튼으로 접을 수 있습니다.

## 시작하기

Node.js 20 이상, Claude API 키, Supabase 프로젝트가 필요합니다.

1. https://console.anthropic.com 에서 Settings → API Keys → Create Key로 키를 발급합니다. 결제 수단을 등록하고 크레딧을 충전해야 쓸 수 있습니다.
2. 패키지를 설치하고 환경 변수 파일을 만듭니다.
   ```bash
   npm install
   cp .env.example .env.local
   ```
   `.env.local`에 Claude 키와 아래 Supabase 값을 채웁니다. 이 파일은 깃에 올라가지 않습니다.
3. Supabase를 설정합니다 (아래 "Supabase 설정").
4. 개발 서버를 실행합니다.
   ```bash
   npm run dev
   ```
   브라우저에서 http://localhost:3000 을 열면 로그인 화면이 나옵니다. 음성 기능은 Chrome이나 Edge에서만 동작합니다.

### Supabase 설정

1. https://supabase.com 에서 프로젝트를 만듭니다. 지역은 Northeast Asia (Seoul)를 고릅니다.
2. Project Settings → API Keys에서 값을 복사해 `.env.local`에 넣습니다.
   - Project URL → `NEXT_PUBLIC_SUPABASE_URL`
   - Publishable key → `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
   - Secret key → `SUPABASE_SECRET_KEY` (서버 전용, 절대 공개하지 않습니다)
3. SQL Editor에 `supabase/migrations/` 의 `0001_init.sql`, `0002_withdrawal.sql`, `0003_consent.sql`, `0004_message_sources.sql`, `0005_plans.sql`, `0006_billing.sql`을 차례로 통째로 붙여넣고 실행합니다. 테이블, RLS, 사진 저장소, 탈퇴 기록, 동의 기록, 검색 출처, 요금제, 결제가 만들어집니다.
4. Authentication → URL Configuration에서 Site URL을 `http://localhost:3000`으로, Redirect URLs에 `http://localhost:3000/auth/callback`을 추가합니다. 배포하면 실제 주소도 추가합니다.
5. Authentication → Sign In / Providers에서 Google과 Kakao를 켭니다. 두 곳 모두 콜백 주소는 Supabase 화면에 나오는 `https://<프로젝트>.supabase.co/auth/v1/callback`을 씁니다.
   - **Google**: Google Cloud Console → API 및 서비스 → 사용자 인증 정보에서 OAuth 클라이언트 ID(웹 애플리케이션)를 만들고, 승인된 리디렉션 URI에 위 콜백 주소를 넣습니다. 클라이언트 ID와 보안 비밀을 Supabase에 붙여넣습니다.
   - **Kakao**: https://developers.kakao.com 에서 앱을 만들고 카카오 로그인을 켭니다. Redirect URI에 위 콜백 주소를 넣습니다. 동의항목에서 닉네임, 프로필 사진, 카카오계정(이메일)을 켭니다. 이메일 동의항목은 비즈 앱에서만 켤 수 있어서, 앱 설정에서 개인 개발자 비즈 앱으로 전환해야 합니다. REST API 키를 Client ID로, 보안 메뉴의 Client Secret 코드를 Client Secret으로 Supabase에 붙여넣습니다.
6. 예전 `data/db.json` 데이터가 있으면 앱에 한 번 로그인한 뒤 옮깁니다.
   ```bash
   node --env-file=.env.local scripts/import-db-json.mjs <로그인한 이메일> --dry-run   # 옮길 내용 확인
   node --env-file=.env.local scripts/import-db-json.mjs <로그인한 이메일>
   ```

| `ONGI_REJOIN_BLOCK_DAYS` | `30` | 탈퇴 후 같은 이메일로 다시 가입할 수 없는 기간(일) |

## 폴더 구조

```
src/
├─ app/
│  ├─ page.tsx                  홈 (선톡, 내 사람들, 최근 상담)
│  ├─ (sessions)/               PC에서 상담 목록 사이드바를 같이 쓰는 화면들 (주소에는 안 붙음)
│  │  ├─ chats/                 상담 목록
│  │  ├─ new/                   새 상담 (캐릭터와 인물 고르기)
│  │  └─ chat/[id]/             채팅 화면, chat/[id]/summary 정리 카드
│  ├─ people/                   인물 목록, 등록, 프로필 (PC에서 사람 목록 사이드바)
│  ├─ me/                       마이페이지 (닉네임, 로그아웃, 탈퇴), me/print 기록 PDF용 인쇄 화면
│  ├─ login/                    로그인 (카카오, 구글)
│  ├─ welcome/                  첫 로그인 동의 화면
│  ├─ privacy/ terms/ ai-notice/ 개인정보 처리방침, 이용약관, AI 답변 안내 (공개)
│  ├─ auth/                     로그인 콜백, 로그아웃
│  └─ api/
│     ├─ chat/                  모드 판단과 답변 스트리밍 (NDJSON)
│     ├─ sessions/              상담 생성·조회, [id]/summary 정리, [id]/apply 프로필 저장
│     ├─ persons/               인물 CRUD, [id]/ask 물어보기
│     ├─ usage/                 오늘 내 사용량 (퍼센트)
│     └─ me/                    내 정보·닉네임·탈퇴, me/export 기록 내려받기
├─ proxy.ts                     로그인 토큰 갱신, 로그인 안 했으면 /login 으로
├─ components/                  캐릭터 얼굴, 아이콘, 하단 메뉴와 PC 세로 메뉴, 목록 사이드바, 인물 패널
└─ lib/
   ├─ characters.ts             캐릭터 성격, 말투, 목소리 설정
   ├─ prompts.ts                안전 규칙, 모드별 지시, 모드 판단 프롬프트
   ├─ claude.ts                 Claude 클라이언트, 모델 설정, 오류 메시지
   ├─ db.ts                     Supabase 저장소 (인물, 상담, 메시지, 사진)
   ├─ auth.ts                   API 에서 로그인 확인 (requireUser)
   ├─ usage.ts                  사용량 기록, 1인·전체 하루 한도
   ├─ supabase/                 서버·브라우저·관리자용 Supabase 클라이언트
   ├─ types.ts                  데이터 타입
   ├─ format.ts                 조사 처리, 날짜, 말풍선 나누기
   └─ speech.ts                 브라우저 음성 인식과 합성
supabase/migrations/            DB 테이블, RLS, 사진 저장소를 만드는 SQL
scripts/import-db-json.mjs      예전 data/db.json 을 Supabase 계정으로 옮기는 스크립트
```

메시지 하나를 보내면 서버에서 두 단계를 거칩니다.

1. **모드 판단**: 최근 대화와 현재 모드를 보고 이번에 어떤 모드로 답할지 정합니다. 구조화 출력으로 결과를 받습니다.
2. **캐릭터 답변**: 안전 규칙, 캐릭터 설정, 인물 프로필로 된 시스템 프롬프트에 모드 지시를 붙여 답변을 스트리밍합니다. 시스템 프롬프트에는 프롬프트 캐싱을 걸어 두었고, 안전 문제로 답변이 거절되면 다른 모델이 자동으로 이어서 답합니다.

## 데이터와 개인정보

- 데이터는 Supabase(Postgres)에 저장되고, 모든 테이블에 RLS를 걸어 **로그인한 본인 데이터만** 읽고 쓸 수 있습니다. 서버 코드에 실수가 있어도 DB가 다른 사람의 상담을 내주지 않습니다.
- 대화 캡처 사진은 비공개 저장소(`chat-images`)에 `본인 id/상담 id/` 경로로 올리고, 화면에는 1시간짜리 서명 URL로만 보여줍니다. 상담이나 인물을 지우면 사진도 같이 지웁니다.
- 사용량 기록은 서버만 쓸 수 있어서, 사용자가 지우거나 고쳐 하루 한도를 우회할 수 없습니다.
- 탈퇴하면 사진 폴더와 계정을 지우고, 인물·상담·메시지·프로필은 DB가 함께 지웁니다. 사용량 기록은 서비스 전체 한도 계산을 위해 계정 연결만 끊고 남깁니다.
- 탈퇴 후 30일 동안은 같은 이메일로 다시 가입할 수 없습니다. 이메일 원문 대신 서버 비밀키로 만든 HMAC 해시만 보관하고, 기간이 지나면 지웁니다. 이메일이 없는 로그인(카카오에서 이메일 동의를 안 한 경우)은 받지 않습니다.
- 정리할 때 건강, 성적 지향, 종교, 연락처, 주소 같은 민감한 정보는 프로필 저장 제안에서 뺍니다.

## 비용과 사용 제한

메시지를 하나 보낼 때마다 모델을 두 번 부릅니다. 한 번은 모드 판단, 한 번은 답변입니다. 비용 대부분은 답변 쪽에서 나옵니다.

- **캐싱**: 시스템 프롬프트와 대화 기록 앞부분을 캐시합니다. 다음 메시지에서는 이미 보낸 부분을 1/10 가격으로 읽습니다. 캐시가 깨지지 않도록 요청 전체의 effort는 고정하고, 해석과 플랜처럼 깊게 생각할 턴만 모드 지시 메시지에서 effort를 올립니다. 보내는 대화 범위도 한 칸씩이 아니라 10개 단위로 밉니다.
- **사용량 기록**: API 응답마다 사용자, 토큰 수, 금액을 `usage` 테이블에 남깁니다.
- **요금제**: 숫자는 모두 `src/lib/plans.ts`에 있습니다. `subscriptions` 테이블에 기간이 남은 행이 있으면 Plus, 없으면 무료입니다.

  | | 무료 | Plus |
  |---|---|---|
  | 캐릭터 답변 모델 | Haiku | Haiku (같음) |
  | 하루 한도 | $0.1 | $0.5 |
  | 하루 웹 검색 | 3회 | 20회 |
  | 상담 하나당 내 메시지 | 40개 | 80개 |
  | 구독 기간 한도 | - | $8 (넘으면 남은 기간은 무료 수준) |

  결제를 붙이기 전에는 `node --env-file=.env.local scripts/set-plan.mjs <이메일> plus|free|expire`로 요금제를 바꿔 테스트합니다.
- **하루 한도**: 내가 오늘 쓴 금액이 요금제 하루 한도에 닿거나, 서비스 전체가 오늘 쓴 금액이 전체 한도(`ONGI_GLOBAL_DAILY_BUDGET_USD` + Plus 인원 × `ONGI_GLOBAL_PER_PLUS_USD`)에 닿으면 대화와 물어보기를 막습니다. 검색 횟수를 다 쓴 날은 검색 없이 답하고, 캐릭터가 그 사실을 한마디로 밝힙니다. 날짜는 서버 위치와 상관없이 한국 시간 자정에 바뀝니다. 정리하기는 그날 상담을 마무리할 수 있도록 계속 쓸 수 있습니다. 사용자에게는 금액 대신 한도 대비 퍼센트를 보여줍니다. 홈 화면에 항상 표시하고, 채팅에서는 80%부터 알립니다.
- **상담 길이**: 상담 하나에서 내 메시지는 요금제에 따라 40개(Plus 80개)까지 보낼 수 있고, 10개 남았을 때부터 남은 횟수를 알려줍니다. 대화가 길수록 메시지마다 다시 보내는 양이 늘어나기 때문입니다. 다 차면 정리하고 새 상담으로 이어가도록 안내합니다.
- **메시지 길이**: 한 번에 2,000자, 사진 5장까지 보낼 수 있습니다.

## Plus 결제 (토스페이먼츠 자동결제)

월 15,000원(부가세 포함) 구독입니다. 코드는 `src/lib/billing.ts`에 모여 있습니다.

- **가입**: `/plus`에서 정기결제에 동의하고 카드를 등록합니다. 돌아온 `/plus/success`에서 서버가 빌링키를 받고 바로 첫 달을 결제합니다.
- **매달 결제**: 토스는 결제 일정을 챙겨 주지 않습니다. 하루 한 번 `POST /api/billing/renew` (헤더 `Authorization: Bearer $CRON_SECRET`)를 부르면 결제일이 된 구독을 결제합니다. 주문번호가 기간과 시도 횟수로 정해지고 결제 전에 `payments` 행을 먼저 넣어서, 여러 번 불러도 한 번만 결제됩니다.
- **결제 실패**: 하루 한 번씩 3번 더 시도하고, 그동안은 Plus를 유지합니다. 모두 실패하면 무료로 돌아가고 빌링키를 지웁니다. 키나 상점 설정 오류는 고객의 결제 실패로 세지 않고 실행을 멈춥니다.
- **해지**: 다음 결제만 하지 않고 남은 기간은 Plus로 씁니다. 기간 안에는 해지 취소가 됩니다. 기간이 끝나면 빌링키를 지웁니다.
- **환불**: 마지막 결제 후 7일 안이고 그 뒤로 상담을 한 번도 하지 않았으면 전액 환불하고 바로 무료로 돌아갑니다.
- **보관**: 빌링키는 `billing_customers`에 두고 서버만 읽습니다. 결제 내역(`payments`)은 본인이 읽기만 하고, 탈퇴해도 계정 연결만 끊고 남깁니다. 탈퇴하면 빌링키를 토스에서 지웁니다.
- **테스트**: 테스트 키로는 실제 돈이 나가지 않습니다. 카드 번호는 앞 6자리만 실제 카드처럼 맞으면 되는데, 상점이 받지 않는 카드 종류면 `NOT_SUPPORTED_CARD_TYPE`이 납니다(BC 계열 `9410…`은 됨). 개발 중에는 아래처럼 직접 부릅니다.

  ```
  curl -X POST -H "Authorization: Bearer $CRON_SECRET" http://localhost:3000/api/billing/renew
  ```
- **실제 서비스 전**: 토스와 자동결제 계약·심사를 거쳐 `live_` 키로 바꾸고, 배포 환경에서 하루 한 번 위 주소를 부르는 스케줄러를 붙입니다.
- **사업자 정보**: 유료 판매에는 상호·대표자·사업자등록번호·통신판매업 신고번호·주소·전화를 약관과 결제 화면에 표시해야 합니다. `src/lib/legal.ts`의 `BUSINESS`를 채우기 전에는 "사업자등록 후 표시"로 나오고, `live_` 키를 넣어도 `/api/billing/prepare`가 결제를 열지 않습니다.
- **약관 버전**: 약관이나 처리방침을 크게 바꾸면 `src/lib/legal.ts`의 `CONSENT_VERSION`과 `POLICY_DATE`를 올립니다. 모든 회원이 다음 접속 때 `/welcome`에서 다시 동의합니다.


## 배포 (Vercel)

1. Vercel에서 **Add New → Project**로 이 GitHub 저장소를 가져옵니다. 설정은 기본값 그대로 둡니다. `vercel.json`이 서버 위치를 서울(`icn1`)로 정합니다.
2. **Settings → Environment Variables**에 `.env.local`과 같은 값을 넣습니다. `NEXT_PUBLIC_`가 붙은 값은 빌드 때 들어가므로, 바꾸면 다시 배포해야 합니다.
3. Supabase **Authentication → URL Configuration**에서 Site URL을 배포 주소로 바꾸고, Redirect URLs에 `https://<배포 주소>/auth/callback`을 추가합니다. 로컬 개발용 `http://localhost:3000/auth/callback`도 남겨 둡니다.
4. 카카오 개발자 콘솔의 **플랫폼 → Web 사이트 도메인**에 배포 주소를 추가합니다. 카카오·구글의 Redirect URI는 Supabase 주소(`https://<프로젝트>.supabase.co/auth/v1/callback`)라서 바꾸지 않아도 됩니다.
5. GitHub 저장소 **Settings → Secrets and variables → Actions**에 `APP_URL`(배포 주소)과 `CRON_SECRET`을 넣습니다. `.github/workflows/billing-renew.yml`이 매일 한국 시간 오전 9시쯤 자동 결제를 실행합니다. Actions 탭에서 손으로 돌려 볼 수도 있습니다.

- Vercel 무료(Hobby) 요금제는 상업적 이용이 안 됩니다. 테스트 결제까지는 무료로 쓰고, 실제 결제를 열기 전에 Pro로 바꾸거나 다른 곳으로 옮깁니다.
- AI 답변과 결제를 기다리는 API는 `maxDuration = 300`(초)으로 둡니다.
